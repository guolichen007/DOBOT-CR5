### Rig Consensus 审计结论

### 关键 Bug 修复: R_link_to_optical 约定

**原有 truth 计算使用的 CODE 约定**: optical +z = -link_x (指向相机后方, dot with target = -1.0)
**正确约定**: optical +z = +link_x (指向前方场景, dot with target = +1.0)

修复后 PnP T_FL_FR 误差从 ~2197mm 降至 ~100mm，与 Exp B 结果一致。

### OpenCV 4.2.0 限制
- `solvePnPGeneric(SOLVEPNP_IPPE)` 在 OpenCV 4.2.0 持续失败（dtype bug）
- fallback `solvePnPRansac(IPPE)` 只返回单解
- homography 分解尝试也未成功生成有效第二候选
- **结论**: OpenCV 4.2.0 无法获取 IPPE 双解，branch selection 无法实施

## Objective Audit 诊断结果 (D1-D4 + LOO + Weighting)

### 核心发现: **CASE 2 — 观测系统偏差 (back face 4-5px bias)**

| 诊断 | 结果 |
|------|------|
| D1 COST_TRUTH_CAMERAS | 1766.87 (RMSE=4.842px) |
| D2 COST_WRONG_CAMERAS | 1581.87 (RMSE=4.393px) |
| **Wrong/Truth ratio** | **0.895 (Wrong 低 10.5%)** |
| D3 cost profile | **单调下降**: truth→wrong, 无 local minimum 在 truth |
| D4 back face bias | **FL/back: du=-4.89, dv=-3.68; FR/back: du=-4.46, dv=-4.87** |

### D3 Alpha Sweep 详细

| Alpha | Truth Dist | Cost | RMSE |
|-------|-----------|------|------|
| 0.0 (truth) | 0.0 | 1766.87 | 4.842 |
| 0.5 | 32.2 | 1625.80 | 4.546 |
| 1.0 (wrong) | 64.4 | 1581.87 | 4.393 |

→ **Cost 从 truth 到 wrong 严格单调递减，truth 不是 stationary point**

### D4 Back Face Bias

- YAML 和 Gazebo SDF 的 back face pose 一致 (xyz=[-0.171,0,0], rpy=[0,-π/2,0])
- Back face 是 ChArUco 8×6, 0.24×0.18m 面板
- FL 和 FR 从正面斜角度看 back face 时，角点检测产生 4-5px 系统偏差
- RE 看不到 back face，其 front face residuals 较干净 (mean_du=+0.14, mean_dv=-0.04)

### LOO 分析

- 删除任一 group/face 都导致灾难性退化 → **数据极度稀疏**
- 删除 Group 2: RE → 32000km (唯一提供 RE 约束的组)
- 删除 back face: FR → 1444mm/113°
- 删除 front face: RE → 1e8 km

### Weighting

- RE 占 49% (179/365 pts)
- Group-normalized 后 Wrong/Truth ratio 仍为 0.876
- 加权不是主要问题

### 判定: CASE 2

**Wrong cameras 有更低 cost + back face 存在系统偏差 + cost 从 truth 单调下降。**

Truth 不是当前 measurement objective 的 stationary point。错误的相机位姿通过牺牲 back face 以外观测的精度来"补偿"back face 的 4-5px 偏差，从而降低总 cost。
