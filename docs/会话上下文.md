### 关键 Bug 修复: R_link_to_optical 约定

**原有 truth 计算使用的 CODE 约定**: optical +z = -link_x (指向相机后方, dot with target = -1.0)
**正确约定**: optical +z = +link_x (指向前方场景, dot with target = +1.0)

- RE 占 49% (179/365 pts)
- Group-normalized 后 Wrong/Truth ratio 仍为 0.876
- 加权不是主要问题

### 判定: CASE 2

**Wrong cameras 有更低 cost + back face 存在系统偏差 + cost 从 truth 单调下降。**

Truth 不是当前 measurement objective 的 stationary point。错误的相机位姿通过牺牲 back face 以外观测的精度来"补偿"back face 的 4-5px 偏差，从而降低总 cost。

**代码位置**: `pnp_solver.py:268` — `valid = [c for c in candidates if c["positive_depth_ratio"] > 0.5]`

## V8.7 Counterfactual PnP + Edge Scale Diagnosis — 2026-07-30 (完成)

### 因果链推进

**V8.6 假设**: FL/right dv=-0.7px → planar PnP 39mm 深度偏差
**V8.7 counterfactual 实验**: 对 detected corners 施加 dv=+0.7px (反方向补偿) → PnP 深度几乎不变

→ **dv=-0.7px 不是根因！** 单纯的 corner shift 不会导致 planar PnP 深度大幅变化，因为有 IPPE 的内部补偿。

### Edge Scale 分析

测量 detected corner edges vs truth edges：
```
detected_edge_px / truth_edge_px = scale
```
- 对 right face：mean scale ≈ 1.043 (detected edges 比 truth 大 4.3%)
- planar PnP 深度误差：z_est / z_true ≈ 1/scale → z 低估 ~37mm
- **预测: Δz = -37mm；实际: Δz = -39mm → 解释度 94%**

### 结论
根因是 **edge scale expansion**（检测角点系统性外扩），不是 corner position shift。
Edge scale 1.043 解释了 94% 的 PnP 深度误差。
